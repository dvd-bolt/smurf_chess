# 👑 Chess Sensei — Smart Assistant (Manifest V3)

Шахматный ассистент для браузера с NNUE, человеческими профилями выбора ходов, шахматными персонами, памятью планов и задержкой от реальных часов.

## Игра по рейтингу — 1.3.0

Режим по умолчанию **«Игра по рейтингу ELO»** ограничивает силу самого Stockfish, вместо выбора из его трёх лучших ходов. После обновления старые настройки режима один раз переводятся в рейтинговый режим с целью 55%. Сила фиксируется на партию; после изменения уровня начните новую партию.

- При равном номинальном уровне ориентир — **55% набранных очков**: победа = 1, ничья = ½, поражение = 0. Это не обещание 55% чистых побед. Теоретическое небольшое преимущество соответствует примерно +35 пунктам ELO; локальные поправки для верхних уровней уменьшают избыточную силу короткого NNUE-поиска.
- От штатного нижнего предела движка 1320 используются `UCI_LimitStrength` и `UCI_Elo`. Выбирается именно ограниченный по силе `bestmove`, который может отличаться от первой линии анализа. Для 800–1300 добавлена модель ошибок среди всех легальных ходов; её параметры находятся в `engine/rated_profile.js`.
- Дебютная книга, сноубол и персоны не переопределяют рейтинговый ход. Кандидаты анализа видны, но для выполнения доступен выбранный профилем ход. Re-roll повторяет зафиксированный выбор. Обязательный предел 160 cp в этом режиме не действует.
- Анализ точности и оценка дополнительного хода выполняются без ограничения силы; каждый поиск явно переключает настройки. NNUE и Python Bridge передают фактически применённый ELO и выбранный ход. Если резервный движок не поддерживает ограничение, HUD сообщает об этом, вместо незаметного перехода к полной силе.
- Адаптация в рейтинговом режиме использует долю очков, включая ничьи; старый человеческий режим по-прежнему использует долю побед. История разных режимов разделена.
- **«Сильная игра — без ограничения ELO»** сохраняет прежний селектор с фильтром зевов. **«Человеческая игра»** сохраняет эвристические персоны; её внутренние единицы силы не являются откалиброванным рейтингом.

Шкала привязана к ограничению Stockfish. Она не тождественна рейтингам людей или именным ботам Chess.com/Lichess; на силу влияют движок и контроль времени. Официальная [документация Stockfish](https://official-stockfish.github.io/docs/stockfish-wiki/Stockfish-FAQ.html) описывает ограничения силы. Ниже 1320 абсолютный рейтинг оценивается через матчи с опорным уровнем; матчи двух низких профилей проверяют только их относительную силу.

После обновления перезагрузите расширение в браузере и полностью обновите вкладку клавишей F5. Для Python Bridge также перезапустите сервер.

Проверки версии 1.3.0:

```bash
npm ci
npm test
npm run test:bridge
npm run test:browser
npm run test:matches
```

Браузерные тесты используют установленный Edge либо `BROWSER_PATH`. Матчи по умолчанию проверяют семь уровней с парными цветами, разными дебютами и отдельными seed. Настройки: `MATCH_LEVELS`, `MATCH_PAIRS`, `MATCH_MS`, `MATCH_PLIES`, `MATCH_CONCURRENCY`, `MATCH_REPORT`. Для относительной проверки равных низких уровней задайте `MATCH_OPPONENT=equal`; для проверки разницы в силе можно задать `MATCH_REFERENCE=2000`. Незавершённые партии сохраняются отдельно и не становятся ничьими или поражениями. Отчёты находятся в `test/rated_*_report.json`; [методика и результаты](test/RATING_CALIBRATION.md) описывают ограничения коротких серий.

## ✨ Основные возможности

* 🏹 **Визуализация Топ 1–3 на доске**: одновременная отрисовка цветных неоновых стрелок (🟢 Зеленая для Топ-1, 🔵 Синяя для Топ-2, 🟠 Оранжевая для Топ-3, 🟣 Фиолетовая для дебюта) с акцентным кольцом для хода, выбранного под текущий ELO.
* 🎯 **Переключатель режима стрелок (`🎯 3` / `🎯 1`)**: возможность переключаться в один клик между показом всех 3 вариантов и одного конкретного хода.
* 📋 **Интерактивный список MultiPV в HUD**: до 8 кандидатов в человеческом режиме с реальными оценками в пешках (`+0.35`) или матах (`#M3`). На доске показываются первые три и выбранный вариант.
* 🤖 **Тренировка с ботами Chess.com (`/play/computer`)**: распознавание доски и паузы по сложности позиции даже без часов. Книжные ходы и очевидные взятия выполняются быстрее, сложные решения — медленнее.
* ⚡ **Гибридный движок (NNUE WASM + JS + Python Bridge)**: автономный запуск Stockfish 19 Lite через WASM со встроенной NNUE прямо в браузере с поддержкой переключения на мощный Python Bridge и автоматическим мягким фоллбэком, если локальный сервер не запущен.
* 🎲 **Умная рандомизация Топ 1–3**: выбор хода по весам ELO со сглаживанием резких движковых тактик.
* 🛡️ **Защита от критических ошибок (Blunder Filter)**: отсечение опасных ходов, если они уступают лучшей линии более чем на 1.6 пешки.
* ❄️ **Стратегия «Сноубол» (Smooth Snowballing)**: постепенное наращивание позиционного давления, переход в выигранный эндшпиль и надежная защита.
* ⏱️ **Динамический расчет времени от часов (Human Delay)**: расчет реалистичного времени на ход с индикатором обратного отсчета **«ХОДИ СЕЙЧАС»**.
* 📖 **Дебютная книга (Opening Book)**: база из более 5,300 позиций гроссмейстерских дебютов с мгновенным показом названия.
* 🎯 **Контроль точности партии (Live Accuracy)**: отслеживание среднего CPL и процента точности с предупреждением, если игра идет слишком чисто для выбранного ELO.
* 🎲 **Кнопка Re-roll**: возможность мгновенно перевыбрать другой допустимый ход в один клик.
* ⌨️ **Горячая клавиша `H`**: мгновенно скрыть / показать стрелки на доске.
* 🤖 **Автоматически выполнять ходы**: переключатель в настройках, по умолчанию выключен. На своём ходу выполняет выбранный вариант после таймера обдумывания, либо сразу после расчёта при выключенной задержке. Отключение отменяет ожидающий автоход; при отказе доски повторных попыток для того же расчёта нет.
* 🔄 **Восстановление движка**: при отказе обоих процессов Stockfish расширение один раз пересоздаёт фоновый документ и повторяет расчёт. Если сбой остаётся, HUD показывает причину ошибки и корректный статус движка.
* Если процессы Worker недоступны, встроенный классический Stockfish запускается в отдельном локальном фрейме фоновой страницы. HUD показывает «Stockfish JS (резерв)»; NNUE в этом режиме не используется. Фрейм сохраняет очередь UCI и не зависит от отрисовки скрытой страницы.
* После перезагрузки или обновления расширения полностью обновите вкладку Chess.com/Lichess клавишей F5. Переход к новой партии внутри сайта может сохранять старый код. Номер загруженного виджета виден рядом с его названием; устаревший контекст расширения блокирует расчёт и автоходы и сообщает о необходимости F5.
* ⌨️ **Пробел**: выполнить выбранный в HUD ход. Работает только на своём ходу для актуальной позиции; ввод текста и удержание клавиши не отправляют ходы. При отказе сайта принять программное нажатие HUD предлагает сделать ход мышью.

## ⚡ Опционально: подключение нативного Stockfish (Python Bridge)

По умолчанию расширение использует Stockfish 19 Lite single-thread WASM со встроенной сетью `nn-61e7af4bb97d.nnue`. Все файлы находятся в расширении: интернет и запуск консоли не нужны. При сбое WASM автоматически включается классический JS-движок.

Если вы хотите использовать нативный файл `stockfish.exe`:
1. Поместите бинарник в `bridge/stockfish.exe`, добавьте Stockfish в PATH или задайте переменную `STOCKFISH_PATH` с полным путём. Затем запустите локальный мост:
   ```bash
   python bridge/local_server.py
   ```
2. Откройте окно расширения (клик на значок 👑) и включите тумблер **«Локальный Stockfish (Python Bridge)»**.
3. Расширение начнет отправлять запросы напрямую в ваш локальный движок на 4 потока CPU.

## Исправления 1.0.2

- Полный FEN восстанавливается из атрибута доски, легальных переходов или истории ходов. Права на рокировку не восстанавливаются после возврата короля/ладьи; учитываются взятие на проходе и счётчики. Если история неизвестна, анализ приостанавливается до получения достоверной позиции.
- Все настройки применяются на открытой странице. При выключенном Bridge запросы к localhost не выполняются.
- Поиски движка выполняются последовательно с UCI-handshake, ограничением времени и перезапуском Worker после сбоя. Встроенный движок — Stockfish Multi-Variant 2019 в asm.js; нативный движок определяется установленным бинарником.
- Тестовая доска проверяет легальность ходов, включая рокировку, взятие на проходе и превращение; скрипты совместимы с CSP расширения.
- Точность — приблизительная оценка по разнице оптимальных оценок до и после фактического хода игрока. Книжные рекомендации и ход соперника не считаются потерей игрока. Позиции с матовыми оценками пропускаются; история сбрасывается при новой партии или переходе по истории.

Последняя команда требует доступный пакет Playwright и установленный Edge (либо переменную BROWSER_PATH). Она проверяет автономный стенд и распакованное расширение с реальным движком.

## NNUE и шахматные персоны — 1.1.0

Выберите стиль в popup или в списке HUD. Настройка `aiPersona` синхронизируется между открытыми вкладками без перезагрузки:

- ⚡ Баланс — дебютная книга, веса ELO и сноубол.
- ⚔️ Таль — повышенный вес шахов, взятий и жертв пешек с проверенной инициативой в PV.
- 🛡️ Карпов — развитие, централизация, связные пешки и уход незащищённых фигур из-под атаки; ранние вылазки ферзя получают штраф.
- 👑 Капабланка — размен обеих ферзей при перевесе от 100 cp (+1 пешка), активный король и проходные в эндшпиле.

Это эвристики выбора среди безопасных MultiPV-кандидатов. Они не воспроизводят партии или мышление исторических игроков. Персоны с именами обходят дебютную книгу и анализируют позицию, чтобы стиль учитывался также в дебюте. При неизбежном проигрыше фильтр оставляет лучший доступный ход.

Защита от потерь больше 160 cp обязательна для всех стилей. Старое сохранённое значение `blunderFilter: false` игнорируется; переключатель в popup теперь показывает обязательную защиту. Опасные линии отмечаются в списке и недоступны для выбора; стрелки рисуются только для допустимых кандидатов.

Бейдж показывает фактический источник: `NNUE (WASM)`, `Native`, `JS (Auto)` или `Книга`. В подсказке NNUE видны имя движка, сеть и длительность поиска. Python Bridge остаётся опциональным и имеет приоритет только при включённой настройке.

[Происхождение и контрольные суммы NNUE](vendor/stockfish-nnue-assets.json), [GPLv3](vendor/STOCKFISH-LICENSE.txt), [исходники и сборка](https://github.com/nmrugg/stockfish.js/tree/v19.0.0). Файлы релиза переименованы, их содержимое не изменено. Отдельные веса не скачиваются; WASM занимает 1 787 571 байт. Время зависит от позиции, MultiPV, глубины и компьютера; рейтинг ELO — профиль выбора, а не измеренная сила движка.

Основные команды `node test/run_tests.js` и `node test/regression_tests.js` включают тесты персон и реальный Node-поиск NNUE. Отдельно можно запустить `node test/persona_tests.js`, `node test/nnue_tests.js`, `node test/timing_tests.js` и `node test/browser_tests.js`. Браузерные тесты проверяют NNUE, офлайн-файлы, откат на JS, интерфейс и синхронизацию настроек в распакованном расширении.

## Время на ход — 1.1.6

При включённой человеческой задержке бюджет хода равен 75% оставшегося времени, разделённым на ожидаемое число ходов (не меньше 16). Добавление учитывается только при наличии явного `data-increment-seconds` в DOM; если сайт его не сообщает, используется бюджет без добавления. Модель различает книгу, развитие фигур, единственный ход, очевидное взятие, близкие по оценке варианты, защиту от шаха, рискованные размены и превращение. Это эвристическая оценка сложности, а не гарантия, что взятие безопасно во всех продолжениях.

Небольшой разброс сохраняется в пределах одного хода. Расчёт движка входит в общее время: выбор другого кандидата, Re-roll и изменение настроек не запускают ожидание заново. HUD показывает причину задержки. По мере уменьшения часов максимальная пауза сокращается; при 8 секундах она не превышает 0.56 секунды. Длительные паузы исключены в цейтноте, поиск сокращается, оценка точности при остатке до 30 секунд пропускается. Скорость самого движка и взаимодействия с доской зависит от компьютера.

## Человеческая игра и адаптивная сила — 1.2.0

В настройках выберите **«Человеческая игра»**, включите **«Адаптивная сила»** и оставьте цель **65%**. Начните новую партию: профиль силы и персоны фиксируется на партию. Старые настройки сохраняются, по умолчанию остаётся прежний режим **«Надёжная игра»**. Изменение силы/персоны посреди партии вступает в полный эффект со следующей партии; такую смешанную партию сохраняем в истории, но исключаем из калибровки.

Человеческий селектор оценивает качество и распознаваемость до восьми проверенных движком вариантов. Он учитывает навыки, сложность, часы и план: развитие, защиту, упрощение, атаку или продвижение проходной. Неточности зависят от силы и трудности; сильные профили выбирают точнее. Знакомые дебюты образуют небольшой повторяемый репертуар. Рекомендация для партии и полного FEN сохраняется, в том числе после F5; пользователь может изменить её выбором кандидата или Re-roll.

В человеческом режиме допустимы потери больше прежних 160 cp в рамках профиля. Такие варианты не обозначаются как строго безопасные: подсказка показывает потерю. Незаконные и устаревшие ходы исключены всегда. Число кандидатов и бюджет расчёта сокращаются в цейтноте. Время расчёта входит в таймер обдумывания.

Адаптация считает **победы среди всех подтверждённых завершённых партий**, включая ничьи в знаменателе. Группы разделены по сайту, категории/уровню соперника, контролю времени, персоне, режиму и исходной силе. До 20 партий идёт сбор данных; дальше оценка пересматривается каждые 10 новых результатов по окну до 100 партий. Поправка изменяется плавно, на ±40 внутренних единиц силы, только при убедительном выходе за целевой диапазон с учётом неопределённости. Эти единицы не являются измеренным рейтингом. При достижении границы профиля показывается предел силы.

Подтверждаются мат/пат/недостаток материала по FEN и явный результат сайта или стенда. Сдача и таймаут учитываются, если сайт показывает распознаваемый итог. Исчезновение доски и неизвестный итог не становятся поражением. Если сайт изменит разметку результата, такую партию можно оставить неучтённой; проценты не выдумываются. Результат онлайн-партии с известным ID сохраняется один раз даже из нескольких вкладок. Сброс статистики сохраняет профиль активной партии и защиту от повторного учёта старых исходов.

Данные хранятся локально: до 500 подробных исходов, 100 результатов на группу, 16 активных сессий и 5000 ID для дедупликации. Настройки синхронизируются, история партий не отправляется на сервер.

Проверки нового режима:

```bash
node test/human_tests.js
node test/human_match_tests.js
node test/browser_tests.js
python test/test_bridge.py
```

`test/human_match_report.json` — предварительные 24 матча против фиксированных вариантов Stockfish с коротким поиском; отдельные seed использованы для проверки. В них потери сильного профиля заметно ниже слабого. Выборка мала, 5 партий не закончились в лимите и исключены из доли побед. **Достижение 60–70% побед этим отчётом не подтверждено**: цель зависит от соперников и дальнейших реальных результатов. Объём матчей можно увеличить через `MATCH_SEEDS` и `MATCH_PLIES`. Полная спецификация: [PLAN_HUMAN_PLAY.md](PLAN_HUMAN_PLAY.md).
